# SYS-002 系统部署设计

> 版本：v1.0 ｜ 日期：2026-09-30
> 关联文档：SYS-001, SYS-003, SYS-004, MOD-COM-001

---

## 1. 概述

### 1.1 文档目的

定义企业多模态数据中台 MVP 的部署形态，涵盖 Docker Compose 编排、容器资源配额、网络分区、数据卷、环境分级与监控告警，作为运维部署的直接依据。

### 1.2 读者对象

- 运维工程师：按本文档执行部署与监控
- 架构师：评审部署形态是否满足 8GB 内存约束
- 开发工程师：理解应用容器的资源限制与环境变量

### 1.3 术语与缩略语

| 术语 | 含义 |
|---|---|
| core 档 | 必启容器集合：postgres + platform-app + processing-app + portal-nginx |
| label 档 | 可选 profile：额外启用 label-studio 容器 |
| named volume | Docker Compose 管理的命名卷，由 Docker 自动分配宿主机路径 |
| healthcheck | Docker 容器健康检查，决定容器状态与依赖启动顺序 |

---

## 2. 设计目标与约束

### 2.1 功能目标

- `docker compose up -d`（core）在 8GB 内存机器上 3 分钟内全部 healthy
- core 档稳态内存 ≤ 2.5GB；+label 档 ≤ 3.5GB
- 数据卷可整体拷贝迁移，应用重启不丢任务
- 支持 dev / demo / prod 三档环境分级

### 2.2 非功能目标

- 容器故障自动重启（`restart: unless-stopped`）
- 健康检查覆盖所有核心容器
- 关键日志输出到 stdout，由 docker 收集

### 2.3 技术约束

- 单机部署，不引入 Kubernetes
- 外部中间件仅 PostgreSQL 1 个
- 镜像总量 ≤ 2GB
- 所有可变参数走环境变量（`.env` 文件）

## 3. 详细设计

### 3.1 Docker Compose 编排

```yaml
# docker-compose.yml（core 档核心结构）
name: mydatama

services:
  postgres:
    image: postgis/postgis:16-3.4
    environment:
      POSTGRES_DB: mydatama
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      PGDATA: /var/lib/postgresql/data
    volumes:
      - pg-data:/var/lib/postgresql/data
      - ./infra/postgres/init:/docker-entrypoint-initdb.d:ro
    ports:
      - "127.0.0.1:5432:5432"
    deploy:
      resources:
        limits: { memory: 1G, cpus: '1.0' }
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 10
    restart: unless-stopped

  platform-app:
    build: ./backend-java
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/mydatama
      SPRING_DATASOURCE_USERNAME: ${DB_USER}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD}
      JWT_HMAC_SECRET: ${JWT_HMAC_SECRET}
      SERVICE_TOKEN: ${SERVICE_TOKEN}
      JAVA_PROCESSING_BASE_URL: http://processing-app:8000
      JAVA_OPTS: "-Xmx640m -XX:+UseG1GC"
    ports:
      - "127.0.0.1:8080:8080"
    depends_on:
      postgres: { condition: service_healthy }
    deploy:
      resources:
        limits: { memory: 768M, cpus: '1.0' }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 15s
      timeout: 5s
      retries: 10
    restart: unless-stopped

  processing-app:
    build: ./processing-service
    environment:
      DB_URL: postgresql://postgres:5432/mydatama
      DB_USER: ${DB_USER}
      DB_PASSWORD: ${DB_PASSWORD}
      JWT_HMAC_SECRET: ${JWT_HMAC_SECRET}
      SERVICE_TOKEN: ${SERVICE_TOKEN}
      JAVA_INTERNAL_BASE_URL: http://platform-app:8080
      STORAGE_ROOT: /data
      WORKER_THREADS: 2
      POLL_INTERVAL: 2
    volumes:
      - mydatama-data:/data
    ports:
      - "127.0.0.1:8000:8000"
    depends_on:
      postgres: { condition: service_healthy }
    deploy:
      resources:
        limits: { memory: 384M, cpus: '1.0' }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 15s
      timeout: 5s
      retries: 10
    restart: unless-stopped

  portal-nginx:
    image: nginx:1.27-alpine
    volumes:
      - ./frontend/dist:/usr/share/nginx/html:ro
      - ./infra/nginx/portal.conf:/etc/nginx/conf.d/default.conf:ro
    ports:
      - "8090:8090"
    depends_on:
      platform-app: { condition: service_healthy }
      processing-app: { condition: service_healthy }
    deploy:
      resources:
        limits: { memory: 64M, cpus: '0.2' }
    restart: unless-stopped

  # label 档（可选）
  label-studio:
    profiles: ["label"]
    image: heartexlabs/label-studio:1.10.0
    environment:
      LABEL_STUDIO_DISABLE_SIGNUP: "true"
      LABEL_STUDIO_USERNAME: ${LS_USER}
      LABEL_STUDIO_PASSWORD: ${LS_PASSWORD}
      LABEL_STUDIO_SERVICE_TOKEN: ${LS_SERVICE_TOKEN}
    volumes:
      - ls-data:/label-studio/data
    deploy:
      resources:
        limits: { memory: 1G, cpus: '0.5' }
    restart: unless-stopped

volumes:
  pg-data:
  mydatama-data:
  ls-data:
```

### 3.2 容器资源配额

| 容器 | 内存限制 | CPU 限制 | Xmx / 关键调优 | 启动顺序 |
|---|---|---|---|---|
| postgres | 1.0GB | 1.0 | shared_buffers=512MB, work_mem=4MB, max_wal_size=1GB | 1 |
| platform-app | 768MB | 1.0 | Xmx640m, G1GC | 2（依赖 postgres healthy） |
| processing-app | 384MB | 1.0 | PYTHONUNBUFFERED=1, WORKER_THREADS=2 | 2（依赖 postgres healthy） |
| portal-nginx | 64MB | 0.2 | worker_processes=1 | 3（依赖后端 healthy） |
| label-studio | 1.0GB | 0.5 | — | 可选 |
| **core 合计** | **≤ 2.5GB** | — | — | — |
| **+label 合计** | **≤ 3.5GB** | — | — | — |

### 3.3 数据卷设计

| 卷名 | 挂载点 | 用途 | 备份策略 |
|---|---|---|---|
| pg-data | `/var/lib/postgresql/data` | PostgreSQL 数据目录 | `pg_dump` 每日全量 |
| mydatama-data | `/data`（processing-app） | 上传与处理文件 raw/processed/thumb | 整卷 tar 备份 |
| ls-data | `/label-studio/data` | Label Studio SQLite 与上传 | 整卷 tar 备份（可选） |

**`mydatama-data` 目录结构**：

```
/data/
├── raw/                  # 原始上传文件（按日期分桶）
│   └── 2026/09/30/
│       └── {file_id}_{原始名}
├── processed/            # 处理后成品
│   └── 2026/09/30/
│       └── {file_id}_processed.{ext}
├── thumb/                # 缩略图（图像/视频首帧）
│   └── {file_id}_thumb.jpg
└── quarantine/           # 坏行隔离记录
    └── {file_id}_badrows.csv
```

**端口暴露策略**：

| 端口 | 容器 | 暴露范围 | 说明 |
|---|---|---|---|
| 8090 | portal-nginx | 0.0.0.0（生产绑 localhost + 反代 HTTPS） | 唯一对外入口 |
| 5432 | postgres | 127.0.0.1 only | 仅本机管理访问 |
| 8080 | platform-app | 127.0.0.1 only | Nginx 内部转发 |
| 8000 | processing-app | 127.0.0.1 only | Nginx 内部转发 |
| 8080 | label-studio | 不暴露 | Nginx `/label-studio/**` 代理 |

### 3.5 环境变量清单

`.env.example` 完整列表：

```bash
# 数据库
DB_USER=mydatama
DB_PASSWORD=change_me_in_prod
POSTGRES_DB=mydatama

# JWT 与服务令牌（生产请用 openssl rand -hex 32 生成）
JWT_HMAC_SECRET=change_me_to_32_bytes_min_length_secret_value_here
SERVICE_TOKEN=change_me_service_token_for_internal_api_calls

# Label Studio（可选）
LS_USER=admin@mydatama.local
LS_PASSWORD=change_me_ls_password
LS_SERVICE_TOKEN=change_me_ls_service_token

# Java 应用
JAVA_OPTS=-Xmx640m -XX:+UseG1GC

# Python 处理服务
WORKER_THREADS=2
POLL_INTERVAL=2
MAX_FILE_SIZE_MB=200
AUDIT_RETENTION_DAYS=180

# 限流
RATE_LIMIT_LOGIN_PER_MIN=5
RATE_LIMIT_API_PER_SEC=20
```

### 3.6 环境分级

| 环境 | 用途 | 配置差异 | 启动命令 |
|---|---|---|---|
| dev | 本地开发 | 不限制内存，挂载源码，HMR | `docker compose -f docker-compose.yml -f docker-compose.dev.yml up` |
| demo | 演示/培训 | core 档默认配置 | `docker compose up -d` |
| prod | 生产 | 绑 localhost + 外置 HTTPS 反代，`AUDIT_RETENTION_DAYS=365` | `docker compose up -d` + 外置 Nginx HTTPS |

### 3.8 健康检查策略

| 容器 | 检查命令 | 间隔 | 超时 | 重试 | 启动宽限 |
|---|---|---|---|---|---|
| postgres | `pg_isready -U $USER -d $DB` | 10s | 5s | 10 | 30s |
| platform-app | `curl -f http://localhost:8080/actuator/health` | 15s | 5s | 10 | 60s |
| processing-app | `curl -f http://localhost:8000/health` | 15s | 5s | 10 | 30s |
| portal-nginx | `curl -f http://localhost:8090/` | 30s | 3s | 3 | 5s |
| label-studio | `curl -f http://localhost:8080/health` | 30s | 5s | 5 | 60s |

### 3.9 监控告警

MVP 不引入 Prometheus/Grafana，采用轻量方案：

| 监控项 | 实现方式 | 告警阈值 |
|---|---|---|
| 容器存活 | `docker compose ps` + cron 检查 | 任一容器 unhealthy 持续 1 分钟 |
| 内存使用 | `docker stats --no-stream` | core 合计 > 2.5GB |
| 任务积压 | Java `/actuator/info/queue-size` | PENDING 任务 > 50 |
| 处理失败率 | Java 审计表近 1h 失败率 | > 20% |
| 磁盘使用 | `df -h /var/lib/docker/volumes` | > 80% |

**告警方式**：演示阶段仅日志输出 + 容器状态；生产环境接入企业微信/钉钉 webhook（预留配置项 `ALERT_WEBHOOK_URL`）。

### 3.10 备份与恢复

| 备份对象 | 方式 | 频率 | 保留期 |
|---|---|---|---|
| PG 数据库 | `pg_dump -Fc mydatama > backup.dump` | 每日 02:00 | 7 天滚动 |
| 文件卷 | `tar -czf data.tar.gz /var/lib/docker/volumes/mydatama-data` | 每日 02:30 | 7 天滚动 |
| 配置 | git 仓库 + `.env.production` 单独备份 | 变更即提交 | 永久 |

**恢复演练**：每月执行一次恢复到测试环境验证备份有效性。

## 5. 设计决策记录

| 决策编号 | 决策内容 | 理由 |
|---|---|---|
| ADR-002-01 | postgis/postgis:16-3.4 官方镜像 | 同时提供 PG 16 与 PostGIS 3.4，避免二次构建 |
| ADR-002-02 | postgres 端口仅绑 127.0.0.1 | 安全考虑，不对外暴露 DB |
| ADR-002-03 | platform-app Xmx640m + G1GC | 实测 G1GC 在 512MB+ 堆下停顿可控 |
| ADR-002-04 | processing-app 限制 384MB | Python + pandas 处理小文件足够；大文件靠流式 |
| ADR-002-05 | portal-nginx 单独容器而非 platform-app 内嵌 | 静态资源与 API 解耦，便于 CDN 演进 |
| ADR-002-06 | label-studio 走 profile 而非默认启用 | 8GB 机器默认流畅，需要标注时显式启用 |
| ADR-002-07 | init 脚本按字典序执行 | PG 官方约定，便于后续追加迁移脚本 |

## 6. 验收标准

- [ ] `docker compose up -d` 在 8GB 机器上 3 分钟内 4 容器全部 healthy
- [ ] `docker stats` core 合计稳态内存 ≤ 2.5GB
- [ ] `docker compose -f docker-compose.yml --profile label up -d` 5 容器合计 ≤ 3.5GB
- [ ] 容器故障 `docker compose restart <svc>` 后自动恢复 healthy
- [ ] `.env` 缺失时启动失败并提示明确错误
- [ ] 数据卷可在另一台机器恢复并启动
- [ ] `infra/postgres/init/` 执行后五 schema 与种子数据就位
