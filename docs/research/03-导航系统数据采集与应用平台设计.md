> 版本：V1.0（总体设计，技术实现细节留待后续评审确定）
> 编制日期：2026-09-30
> 关联文件：《关于基于北斗规模应用的交通运输数智融合与风险减量平台项目的说明 V1.0》
> 文档定位：面向道路货运车辆"单北斗视频智能终端"规模化换装背景，设计导航（定位/轨迹）与驾驶行为视频数据的采集、治理、应用全链路平台，为后续开发提供需求依据与技术方向。

# 第一部分　功能需求设计

## 1. 总体需求理解

### 1.1 平台定位

平台是"基于北斗规模应用的交通运输数智融合与风险减量平台"的**数据底座与数据中枢**，对上支撑风控运营中心（感知—预警—干预闭环）、行管部门"一屏统览"、保险风险减量、企业安全管理与驾驶员健康生态；对下接入百万级单北斗视频智能终端。

### 1.2 核心数据对象

| 数据域 | 数据对象 | 模态 | 数据量级（单车参考） |
|---|---|---|---|
| 人 | 驾驶员身份、从业资格、行为事件、健康/情绪特征 | 结构化 + 人脸视频 | 事件级，KB～MB/日 |
| 车 | 车辆档案、北斗定位、CAN 总线、报警、终端状态 | 时序结构化 | **约 8.6 万点/日（1Hz 行驶 24h）** |
| 路 | 轨迹、道路匹配结果、路段风险、交通环境 | 时空数据 + 地图 | 与车辆同频 |
| 险 | 保单、理赔、风险评分、保费浮动 | 结构化 | 低频 |
| 媒体 | DSM 驾驶员视频、ADAS 前向视频、事件抓拍 | **视频/图像流** | 全量 10～30GB/日（通常不全量上传） |

### 1.3 设计基线指标（需求级）

- 接入规模：试点 1 万辆 → 区域 10 万辆 → 规划百万级；
- 实时性：事件报警端到端（终端触发→坐席弹窗）**≤3 秒**；健康风险预警由秒级延伸至**分钟级前瞻**；
- 可用性：核心服务 ≥99.9%；
- 合规：满足等保三级、《数据安全法》《个人信息保护法》及交通运输行业数据管理要求。

## 2. 数据采集范围、频率与精度要求

### 2.1 采集范围

单北斗视频智能终端集成 GNSS 定位、CAN 总线读取、ADAS（高级驾驶辅助）、DSM（驾驶员状态监控）等能力，采集数据分为五类：

**（1）位置与运行状态类**
北斗/GPS 定位（经度、纬度、海拔、速度、方向、定位状态、卫星数、HDOP 精度因子）、累计里程、终端时间戳、点火/熄火状态。

**（2）车辆总线类（CAN/OBD）**
车速、发动机转速、油门开度、刹车信号、转向灯、安全带、车门、灯光、胎压（有条件时）；新能源车补充 SOC、电机、充电状态。

**（3）ADAS 前向预警类**
前向碰撞预警（FCW）、车道偏离（LDW）、车距过近（HMW）、行人碰撞（PCW）、城市前碰、限速标志识别等，每类含事件类型、时间、位置、置信度、抓拍图。

**（4）DSM 驾驶员状态类**
疲劳驾驶（闭眼/打哈欠/长时间驾驶）、分心（左顾右盼/低头）、抽烟、接打电话、未检测到驾驶员、身份识别（人脸比对）等事件；条件具备时采集可穿戴设备的心率/血压等体征。

**（5）音视频媒体类**
驾驶员摄像头（DSM）、前向道路摄像头（ADAS）实时视频流与事件片段；可选车厢/侧视摄像头；事件前后抓拍图片。

### 2.2 采集频率与精度

| 数据类型 | 正常频率 | 特殊策略 | 精度/质量要求 |
|---|---|---|---|
| 北斗定位 | 行驶 **1Hz（1 次/秒）** | 熄火静止降为 0.02Hz（1 次/50 秒）；报警期间提升至 2～4Hz | 单点定位水平误差 ≤10m；支持高精度（RTK/差分）区域 ≤1m；速度分辨率 ≤0.1m/s；时间与平台偏差 ≤1s（NTP/北斗授时） |
| CAN/OBD | 1～10Hz（按信号点） | 变化触发 + 周期上报结合 | 按 SAE J1939/OBD 协议解析，丢包率 <1% |
| ADAS/DSM 事件 | **事件触发实时上报** | 附带抓拍图 1～3 张 | 事件误报率（模型侧）目标 <5%，漏报率 <3%；时间/位置与事件强绑定 |
| 心跳与在线状态 | 1 次/30 秒 | 离线判定阈值 3 个心跳周期 | — |
| 实时视频 | 按需拉流（坐席/监管调阅） | 事件触发自动推流 30～120 秒 | 见 §4 视频专项设计 |
| 事件视频片段 | 事件触发自动上传（前后各 15～30 秒） | 网络空闲时补传 | 720P 起步、关键场景 1080P |
| 驾驶员健康体征 | 1 次/分钟～5 分钟 | 异常时秒级加密上报 | 设备需具备二类医疗器械或同等可信度论证 |

> 说明：以上频率兼顾"监管有效性"与"流量/存储成本"。1Hz 定位是行业（JT/T 808 苏标/粤标等地方实施规范）主流设定；最终频率以终端招标技术要求和当地行管平台接入规范为准。

### 2.3 终端与协议要求

- 通信协议：定位/事件/指令遵循 **JT/T 808-2019《道路运输车辆卫星定位系统 终端通讯协议及数据格式》**；ADAS/DSM 扩展遵循其地方补充协议（如苏标、川标、粤标）；
- 音视频：**JT/T 1078-2016《道路运输车辆卫星定位系统 视频通信协议》**；
- 设备标准：符合 JT/T 794（终端技术要求）、JT/T 808、GB/T 19056（行驶记录仪）等；
- 传输网络：4G/5G 蜂窝为主，要求终端本地缓存 ≥72 小时，弱网/断网恢复后断点续传；
- 安全：终端与平台双向身份认证，通信加密（国密 SM 算法优先，兼容 TLS）。

## 3. 行车轨迹数据：采集—处理—存储流程

### 3.1 总体流程

```
终端侧          接入层            实时处理层              存储层              应用层
┌──────┐   808报文   ┌─────────┐  ┌──────────────┐  ┌─────────────┐  ┌──────────┐
│北斗终端│ ─TCP/TLS→ │808协议网关│→│ Kafka 消息总线 │→│ Flink 实时作业 │→ │时序数据库   │→ │实时大屏/风控│
│(1Hz)  │            │(Netty集群)│  └──────────────┘  │·校验清洗     │  │(热:30天)    │  │电子围栏/回放│
└──┬───┘            └─────────┘                     │·地图匹配     │  ├─────────────┤  └──────────┘
   │本地缓存72h        ↑ 指令下行                    │·轨迹压缩     │  │关系库(档案)  │
   └─断点续传──────────┘                             │·里程/统计    │  ├─────────────┤
                                                     │·异常点识别   │  │对象存储(冷:  │
                                                     └──────┬───────┘  │ 月度归档Parquet)
                                                              │          └─────────────┘
                                                              └→ 报警/事件 → 风控规则引擎 → 坐席
```

### 3.2 采集与接入

1. **终端上报**：终端以 1Hz 组织 808 位置汇报（0x0200），报警时置位报警标志并附扩展信号；
2. **协议网关**：基于 Netty 构建 TCP 长连接集群，单机支撑 5～10 万连接，百万车辆按 10～20 节点水平扩展；完成报文解码、终端注册鉴权、心跳管理、粘包/拆包处理、指令下行（0x8103 参数设置、0x8105 控制等）；
3. **削峰解耦**：解码后标准化消息写入 Kafka（按车牌/终端号分区，保证单车有序）；
4. **断点续传**：终端缓存补传数据标记补发位，平台可识别并按原始时间戳入库，不污染实时统计。

### 3.3 实时处理（清洗与标准化）

Flink（或同等流计算引擎）逐条处理：

| 处理环节 | 规则示例 |
|---|---|
| 字段校验 | 必填项（时间、经纬度、速度）非空；经纬度范围合法性（中国陆域框定） |
| 异常点剔除 | 瞬时速度 >300km/h、相邻点瞬移（距离/时间得到的速度物理不可能）、定位无效标志点 |
| 漂移抑制 | 与前后点方向/速度矛盾的"漂移点"识别（Kalman 滤波或基于速度约束的判定） |
| 时钟校准 | 以平台接收时间与终端时间差监控终端时钟偏差，>30 秒告警并记录偏移量 |
| 坐标标准化 | 统一转换为 GCJ-02（地图展示）与 CGCS2000/WGS84（分析计算）两套坐标并存 |
| 地图匹配 | 基于路网拓扑做 Map-Matching，吸附到道路并赋予道路 ID、限速、行政区域 |
| 轨迹压缩 | 在线 Douglas-Peucker / 死区算法，将停车、直线匀速段压缩 50%～80%，回放时按精度等级选择 |
| 统计派生 | 实时里程、行驶时长、夜间行驶、行政区划停留、电子围栏进出事件 |
| 质量统计 | 在线统计各企业/终端的在线率、丢点率、合格率，供数据质量监控 |

### 3.4 存储设计（分级 + 冷热）

| 层级 | 存储选型 | 数据 | 保留周期 | 理由 |
|---|---|---|---|---|
| 热 | **时序数据库（TDengine 或 TimescaleDB）** | 秒级轨迹点、CAN 信号 | 30～90 天 | 高写入（百万车 1Hz ≈ 100 万点/秒峰值）、高压缩（10～20 倍）、按车辆/时间分片 |
| 温 | 关系库 PostgreSQL | 车辆/驾驶员/企业主数据、日汇总、报警事件、评分结果 | 3 年 | 事务、关联查询、行级权限 |
| 温 | Redis | 最新位置（Geo）、在线状态、会话、围栏判断 | 7 天滚动 | 亚毫秒级最新位置查询 |
| 冷 | 对象存储（MinIO/OSS）+ Parquet | 月度轨迹归档、年度数据 | ≥3 年（按合规要求） | 成本极低，供历史回放抽样与精算建模 |
| 检索 | Elasticsearch（可选） | 操作/审计/事件检索 | 6 个月以上 | 日志与事件全文检索 |

> 选型说明：TDengine 在国内车联网（特别是北斗部标平台）有大量落地案例，SQL 语法、超级表按设备建模、内置缓存/订阅，与本场景匹配度最高；TimescaleDB 的优势是与 PostgreSQL 同生态、运维简单。**最终选型在详细设计阶段以压测结果为准**（二者取一）。

### 3.5 容量估算示例（1 万辆试点，便于规划资源）

- 轨迹点：1 万辆 × 1 点/秒 × 日均行驶 8 小时 ≈ **2.88 亿点/日**；原始约 20 字节/点 ≈ 5.8GB/日，经时序压缩（15 倍）后约 **0.4GB/日**；
- 事件：按车均 20 条/日估算 ≈ 20 万条/日；
- 视频：若仅事件片段（车均 10 段 × 30 秒 × 1Mbps ≈ 37MB）≈ **0.37TB/日**（万车规模），需重点设计码率与留存策略（见第 4 节）。
- 放大到百万辆：轨迹压缩后约 40GB/日、事件片段 37TB/日——说明**全量视频上传不可行**，"边缘存储 + 按需回传 + 事件片段"是必选路线。

## 4. 驾驶员行为视频：采集—编码—传输—存储（专项设计）

### 4.1 采集

- **通道**：DSM 红外摄像头（对准驾驶员，支持夜间红外）、ADAS 前向摄像头（对准道路）；每通道独立编码；
- **边缘 AI**：终端内置 NPU 运行 ADAS/DSM 识别模型，**事件在边缘产生**，云端做模型下发、版本管理与结果复核（降低带宽与误报）；
- **图像**：事件触发抓拍 1～3 张 JPEG（含时间、经纬度水印）。

### 4.2 编码

| 项 | 选型 | 说明 |
|---|---|---|
| 编码标准 | **H.265(HEVC) 优先，兼容 H.264** | 同等画质比 H.264 节省 30%～50% 带宽；老平台兼容时降 H.264 |
| 分辨率 | DSM 720P（1280×720）足够面部识别；ADAS 1080P | 不盲目追求高分辨率 |
| 码率 | 512kbps～2Mbps（动态码率自适应） | 弱网自动降码率保连续 |
| 帧率 | 15～25fps | DSM 行为识别 15fps 可满足 |
| 音频 | 默认关闭或仅事件录音 | 涉及车内隐私，默认不采集环境音 |
| 封装 | 1078 实时流（PS over RTP/TCP）；片段 MP4 | 与部标平台互通 |

### 4.3 传输

三种模式并存：

1. **实时调阅（拉模式）**：坐席/监管在平台点击"实时视频"→ 平台经 1078 信令（9101/9102 等）通知终端推流 → 流媒体网关接入并转封装为 **HLS/FLV/WebRTC** 供浏览器播放；限时（如单次 ≤10 分钟）、需审批与留痕；
2. **事件片段（推模式）**：边缘判定事件后自动上传前后 15～30 秒片段，走 HTTP(S)/分片上传，支持断点续传与 Wi-Fi 优先（车辆回场时走场站 Wi-Fi，省流量费）；
3. **定时抓拍/巡检**：按策略定时上传抓拍图用于设备状态与在岗核验。

流媒体网关推荐采用成熟开源媒体服务器（如 ZLMediaKit，国产、高性能、1078 生态适配广泛）承载协议转换与分发。

### 4.4 存储与调阅

```
事件片段/抓拍 → 对象存储（桶内按 日期/企业/车牌/事件类型 分区）
             → 关系库只存元数据（URL、时长、事件、密级、保留期）
实时流       → 不落盘（默认）；风控处置需要时可边录边存
全量视频     → 终端本地 TF/硬盘循环覆盖（≥7～15 天），事故时按指令回传
```

- **保留策略**：一般事件片段 30～90 天；涉及事故/理赔/执法的证据片段标记"保全"，按案件周期长期保存并防篡改（哈希上链/写入 WORM 存储）；
- **隐私保护**：视频默认在边缘对无关乘客区域不做采集；调阅鉴权到"人"，加水印（调阅人账号/时间），所有播放、下载行为审计；
- **生命周期自动清理**：到期对象由存储生命周期策略删除并记录销毁日志。

## 5. 数据治理与合规应用模块

对应项目说明中"数据治理与合规应用"建设内容，平台内嵌治理能力，而非另建独立系统。

### 5.1 数据清洗

- 规则库覆盖：位置异常、时间异常、事件逻辑矛盾（如熄火状态下报急加速）、重复报文、字段缺失；
- 脏数据不直接删除：落入"隔离区"并打标，支持人工复核与回流，保证可追溯；
- 终端画像：按终端统计合格率，反推设备质量，支撑换装验收（不合格批次终端预警）。

### 5.2 数据标准化

- 编码统一：各厂商私有报警码 → 国标 808/地方标统一码表；车型、车牌颜色、企业资质等采用交通运输行业标准代码集；
- 单位/格式统一：速度 km/h、距离 m、时间 ISO-8601、坐标体系明确标注；
- 主数据：车辆、驾驶员、运输企业、终端四类主档去重合并，解决"一车多终端、一人多企业挂靠"。

### 5.3 数据质量监控

| 维度 | 指标示例 | 阈值 |
|---|---|---|
| 完整性 | 轨迹丢点率、事件抓拍缺失率 | 丢点率 <0.5%（在网行驶时段） |
| 准确性 | 定位异常点比例、CAN 越界值比例 | <0.1% |
| 一致性 | 主档与终端上报 VIN/车牌一致率 | 100% 纳管目标 |
| 及时性 | 事件端到端时延、时钟偏差 | 事件 ≤3s；时钟偏差 ≤1s |
| 唯一性 | 重复报文率 | <0.01% |

提供质量大盘、按企业/终端下钻、质量问题工单与整改闭环；质量结果与终端考核、企业评级挂钩。

### 5.4 数据分类分级与合规检查

- 按《数据安全法》《个人信息保护法》及交通运输/汽车数据安全管理相关规定建立目录：
  - **敏感个人信息**：人脸、身份证号、连续行踪轨迹、健康体征；
  - **重要数据**：车辆规模运行数据、重点区域车流、危化品运输数据；
- 合规规则引擎自动化检查：
  - 数据出境/跨域流动审批（默认禁止，白名单+审批）；
  - 敏感字段是否已脱敏、是否加密存储；
  - 留存周期是否到期、删除是否执行；
  - 调阅权限与审批单是否匹配（无单不可调视频）；
  - 第三方（保险）数据使用是否在授权范围与最小必要边界内；
- 输出合规检查报告，作为行业可复制治理标准的交付物。

### 5.5 数据标注与数据集管理（面向算法训练）

- 视频/图像事件片段经人工/半自动标注（疲劳、分心、情绪等），标注平台集成 Label Studio；
- 数据集构建：面向 ADAS/DSM 模型、情绪识别、疾病特异性算法组织训练集/验证集，记录版本、样本分布、标注一致性（Kappa）、质量评分；
- 敏感样本（人脸）在训练前脱敏或采用隐私计算方式训练。

## 6. 数据要素价值释放机制

### 6.1 分析模型体系

| 模型 | 输入 | 输出 | 应用方 |
|---|---|---|---|
| 驾驶行为评分模型 | 急加减速、超速、疲劳、分心等特征 | 0～100 分安全分 + 风险等级 | 保险 UBI、企业管理 |
| 风险事件实时识别（规则+CEP） | 实时轨迹 + ADAS/DSM 事件 | 秒级告警 + 处置工单 | 风控坐席（感知—预警—干预） |
| 事故概率预测 | 历史行为、里程、道路、环境特征 | 未来周期出险概率 | 保险精算、靶向教育 |
| 双模态情绪识别 | 面部视频 + 语音/行为 | 情绪状态、心理风险标签，分钟级预警 | 健康关怀、坐席干预 |
| 疾病特异性算法 | 体征 + 行为特征（授权前提下） | 高血压/心源性风险早期筛查 | 健康医疗生态 |
| 路网风险画像 | 轨迹+事件聚合 | 黑点路段、风险热力 | 行管部门、导航预警 |
| 物流效率模型 | 轨迹、停留、空驶识别 | 空驶率、调度优化建议 | 企业降本增效 |

模型管理采用统一 MLOps 流程：训练（离线特征库）→ 评估 → 注册 → 边缘/云端部署 → 监控漂移 → 再训练。

### 6.2 应用接口（数据服务）

| 接口类别 | 方式 | 示例 |
|---|---|---|
| 实时风险服务 | WebSocket / 消息订阅 | 车辆报警事件实时推送至坐席与企业端 |
| 风险查询 | REST API（OAuth2/AppKey） | 投保前查车辆/驾驶员风险评分 |
| 位置与轨迹 | REST + 瓦片/矢量 | 实时位置、历史轨迹回放、围栏管理 |
| 视频服务 | 1078 信令 + HLS/WebRTC | 实时调阅（审批）、证据片段下载（带水印） |
| 数据产品交付 | 数据集订阅 / **隐私计算节点** | 向保险交付脱敏精算样本（原始数据不出域） |
| 监管上报 | 标准转发接口 | 按属地要求向省/市监管平台转发 808 数据 |

所有接口纳入统一 API 网关：鉴权、限流、计量、审计、脱敏策略联动。

## 8. 技术栈选型建议

> 原则：主流成熟、社区活跃、国产化适配可行；一期控制组件数量，可从模块化单体 + 少量中间件起步，按接入规模演进。

| 层 | 选型建议 | 备选/说明 |
|---|---|---|
| 终端/边缘 | 单北斗视频终端（Android/Linux + NPU），H.265 编码，边缘推理模型由云端统一下发 | 终端为硬件招标范围 |
| 接入网关 | Java + **Netty**（808）；**ZLMediaKit**（1078 流媒体，C++ 高性能） | 网关无状态、水平扩展 |
| 消息总线 | **Kafka**（百万 TPS 级、可回溯） | 试点小规模可先用轻量消息队列过渡 |
| 实时计算 | **Apache Flink**（清洗、CEP 复杂事件、围栏） | Flink 与车联网实时场景匹配度最高 |
| 离线计算 | Spark / Flink Batch，调度一期用轻量方案，规模化后引入 **Apache DolphinScheduler** | 见开源调研文档 |
| 时序数据 | **TDengine**（推荐，车联网案例多） | TimescaleDB（PG 生态，运维简单） |
| 业务数据 | **PostgreSQL**（PostGIS 支持空间查询） | MySQL 国产化替代均可 |
| 缓存 | Redis（最新位置/会话/限流） | — |
| 对象存储 | MinIO（私有云）/ OSS（公有云） | S3 协议，可互换 |
| 检索 | Elasticsearch（审计/事件检索，可选） | 规模小可暂缓 |
| 后端 | Java 17 + **Spring Boot 3**，权限用 **Sa-Token**；微服务化时 Spring Cloud Alibaba | 一期模块化单体，按域拆包 |
| 前端 | Vue 3 + TypeScript + Element Plus；地图用高德/天地图 JS API 或 **Cesium**；图表 ECharts；视频 flv.js/webrtc | 大屏 1920/4K 自适应 |
| AI | Python + PyTorch；推理服务 Triton/FastAPI；边缘模型轻量化（剪枝/量化） | 双模态情绪/疾病模型 |
| 隐私计算 | 联邦学习框架（FATE 等）/ MPC / 可信数据空间 | 与保险联合建模场景 |
| 区块链 | 联盟链（Hyperledger Fabric 或国产链） | 证据保全、授权流转存证 |
| 标注 | Label Studio 容器集成 | 见开源调研文档 |
| 部署 | Docker Compose（试点）→ **Kubernetes**（规模化） | 数据库用 StatefulSet/云托管 |
| 可观测 | Prometheus + Grafana + Loki/ELK + SkyWalking | 指标、日志、链路追踪 |

## 9. 部署方案

### 9.1 分阶段部署

| 阶段 | 规模 | 部署形态 | 资源参考 |
|---|---|---|---|
| 试点验证 | ≤1 万辆 | 1 套 Docker Compose / 小 K8s（3 节点），核心组件高可用不做全冗余 | 约 8～12 台 8C16G 等价资源；视频存储按 0.4TB/日×留存期规划 |
| 区域运营 | 10 万辆 | K8s 集群，808 网关/流处理/媒体服务多副本；数据库主从、时序集群、对象存储分布式 | 按容量模型线性扩展 |
| 规模商用 | 百万辆 | 多可用区/两地三中心；异地灾备；多区域风控运营中心边缘下沉 | 容量规划 + 弹性伸缩 + 专线 |

### 9.2 网络与安全分区

```
互联网区(GW) → DMZ(808/1078网关、WAF、抗DDoS) → 应用区(微服务、API网关)
                                              → 数据区(时序/关系库/对象存储，禁止直连公网)
                                              → 管理区(运维跳板、监控、日志审计)
合作方(保险/监管) → 专线/VPN + 数据交换前置机 → API 网关
```

- 可扩展性：网关与计算节点无状态化，按连接数/消费滞后（Kafka Lag）自动扩缩容；时序与对象存储天然水平扩展；
- 高可用：跨 AZ 双活热备，单节点故障自动切换；消息队列与数据库多副本，RPO≈0、RTO 分钟级；
- 性能：1Hz 写入峰值约 100 万点/秒（百万车），通过 Kafka 批攒 + 时序库批量写入承载；实时查询走 Redis 最新位置缓存。

## 10. 数据安全与隐私保护策略

### 10.1 合规对标

- 等保 2.0 **三级**（含安全物理环境、通信网络、区域边界、计算环境、管理中心五大类控制项）；
- 《网络安全法》《数据安全法》《个人信息保护法》《汽车数据安全管理若干规定》及交通运输行业、属地数据管理规范；
- 驾驶员人脸、行踪轨迹、健康信息按**敏感个人信息**单独管理，取得明示授权，遵循最小必要、目的限定。

### 10.2 技术措施

| 领域 | 措施 |
|---|---|
| 身份权限 | 统一认证；RBAC + ABAC（如"企业用户只能看本企业车辆""视频调阅需审批单"）；行列级数据权限；多因子认证（管理员/坐席） |
| 传输安全 | 终端—平台 TLS/国密 SSL；服务间 mTLS；合作方专线/VPN |
| 存储安全 | 敏感字段加密（国密 SM4）存储；对象存储服务端加密 + 版本/锁定；密钥经 KMS/HSM 管理 |
| 脱敏 | 入库静态脱敏（身份证、手机号）；查询/导出动态脱敏；人脸样本训练前脱敏 |
| 视频管控 | 默认不调阅、调阅必审批、播放必水印、操作必审计；证据片段 WORM 防篡改 |
| 隐私计算 | 与保险联合建模采用联邦学习/MPC，**原始数据不出域**；可信数据空间内完成数据产品加工 |
| 存证审计 | 授权记录、数据流转、模型调用关键环节哈希上链；操作日志 ≥6 个月（重要日志按年留存），日志防篡改 |
| 数据生命周期 | 按密级与类别配置保留/归档/销毁策略，到期自动执行并留证；支持个人信息删除/撤回授权请求处理 |
| 终端安全 | 终端一机一密、双向认证、固件签名 OTA、防拆防刷 |

### 10.3 安全运营

建立数据安全责任人制度、数据出境与对外提供审批流、第三方接入安全评估、年度等保测评与渗透测试、应急预案与演练。

## 11. 测试与质量保障方案

### 11.1 测试体系

| 测试类型 | 重点内容 |
|---|---|
| 协议一致性测试 | 使用 808/1078 协议测试工具与真实终端双轨验证：注册鉴权、0x0200 位置、报警位、参数下发、音视频信令互通；覆盖主流终端厂商 |
| 性能压测 | 模拟百万级长连接与 1Hz 上报（自研报文回放工具 + JMeter/wrk），验证网关连接数、Kafka 吞吐、时序写入、端到端时延 ≤3s |
| 流媒体测试 | 并发拉流路数、首屏时间、卡顿率、弱网（丢包/限速/切换基站）适应性、片段上传断点续传 |
| 数据质量验证 | 注入脏数据（漂移点、乱序、重复、缺字段），验证清洗规则与质量大盘准确性 |
| AI 模型评测 | 事件精确率/召回率（误报 <5%、漏报 <3% 目标）、情绪模型在不同光照/遮挡/方言下的鲁棒性、边缘算力下帧率与功耗 |
| 安全测试 | 等保测评、渗透测试、模糊测试（808 报文畸形输入）、越权与脱敏绕过测试、密钥与审计检查 |
| 兼容性测试 | 多品牌终端、多分辨率浏览器、大屏分辨率、移动端 App |
| 容灾演练 | 网关节点宕机、Kafka/数据库主从切换、断网补传、整机房切换 |

### 11.2 质量保障机制

- **环境分层**：开发 → 联调（接真实终端）→ 预生产（全量数据影子）→ 生产；
- **自动化**：CI/CD 流水线集成单元测试、接口自动化、静态扫描（代码 + 依赖漏洞 + 密钥泄露）；
- **数据保障**：上线前数据迁移/校验脚本双人复核；关键指标（在线率、合格率、报警时延）纳入生产大盘与 SLO（99.9%）；
- **验收指标对齐**：终端上线率、数据合格率、风险报警准确率、干预闭环率等业务指标直接作为平台验收项。
