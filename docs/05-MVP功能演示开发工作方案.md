## 1. 演示目标与范围界定

### 1.1 一句话目标

在 8GB 内存机器上 `docker compose up -d` 一键启动，浏览器中完整走通：

```
原始数据上传（北斗/车辆业务模拟数据）
  → 五阶段治理（校验→清洗→标准化→脱敏→登记）
  → 资产目录 + 血缘 + 质量报告（治理效果可视）
  → 数据集构建与版本管理
  → 产品加工（配置→生成→说明书→合规校验）
  → 产品登记挂牌预览 + 导出
  → 大屏全程实时联动
```

### 1.2 MVP 范围调整对照（相对 01 文档）

| 模块 | 01 文档定位 | 本方案定位 | 说明 |
|---|---|---|---|
| IAM 认证权限 | MVP 内 | **MVP 内** | 不变，登录/RBAC 是演示前提 |
| PROC 数据处理 | MVP 内 | **MVP 内（核心）** | 治理链路主体，含质量检测与修复 |
| GOV 资产目录 | MVP 内 | **MVP 内** | 治理成果落点 |
| DS 数据集质检 | MVP 内 | **MVP 内** | 产品生成的原料关闸 |
| **PROD 产品加工** | **MVP 外（P7）** | **MVP 内（核心）** | **本期新增**：产品配置/生成引擎/预览导出/合规校验 |
| SCR 大屏 | MVP 内 | **MVP 内** | 演示串联线，增加产品域指标 |
| TRAJ 轨迹模块 | 设计已完成 | **最低优先级** | 仅保留模拟器产数能力（作为数据源之一），回放/大屏/查询页**不做或最后做** |
| Label Studio 标注 | 可选 profile | **裁剪出 MVP** | 演示走门户内手工标注，不启 label 容器，省内存给 PROD |

### 1.3 新增 prod schema（DDL 设计随 S4 阶段文档产出）

```
prod.product_templates   产品模板（数据集包/API服务/报告 三类）
prod.products            产品实例（名称/版本/原料数据集版本/状态机）
prod.product_artifacts   产品产物（文件包路径/说明书PDF/质量报告引用）
prod.compliance_checks   合规校验记录（规则项/结论/拦阻原因）
```

产品状态机：`DRAFT → CONFIGURED → GENERATED → CHECKING → PASSED/BLOCKED → REGISTERED → LISTED → DELIVERED（演示到 LISTED 即止，交付仅界面示意）`

## 2. 模拟数据准备方案

### 2.1 设计依据

模拟数据严格对齐《03-导航系统数据采集与应用平台设计》的存储格式规范：**JT/T 808-2019** 位置报文字段语义（车牌、经纬度、速度、方向、报警标志）、1Hz 采样、ADAS/DSM 事件码、企业/车辆/终端主数据行业代码集。

### 2.2 数据清单（覆盖四模态 + 治理全场景）

| 文件 | 模态 | 规模 | 内嵌异常（用于演示治理能力） |
|---|---|---|---|
| `vehicle_gps_20260901.csv` | 结构化 | 5 万行 | 手机号/司机身份证敏感列；2% 缺失；1% 重复；经纬度漂移点 50 条；乱序时间 20 条 |
| `vehicle_gps_20260902.csv` | 结构化 | 5 万行 | 同上但**列名顺序不同+编码 GBK**（演示标准化与血缘对比） |
| `fleet_info.xlsx` | 结构化 | 2 千行 | 多 sheet；车牌格式不一；空行；银行卡号列 |
| `driver_events.json` | 结构化 | 1 万条 | 嵌套 JSON；事件码混用厂商私有码与国标码（演示标准化映射） |
| `driver_notes.txt` | 文本 | 500 段 | 含手机号/邮箱明文（演示文本正则脱敏） |
| `vehicle_photos.zip`（20 张） | 图像 | ~40MB | 含 EXIF/GPS 信息（演示剥离） |
| `dashcam_clips.zip`（5 段） | 视频 | ~100MB | mp4/mov 混合格式，含元数据标签 |

### 2.3 生成方式

- `samples/generator/` 下 1 个 Python 脚本（`generate_all.py`），基于 `faker` + 固定随机种子，**可重复生成**；
- 输出直接落到 `samples/` 目录，zip 打包图像/视频；
- 附 `samples/README.md` 说明每个文件的异常注入点与预期治理结果（即"考题与答案"）。

### 2.4 一致性验证

- 字段名/取值域对照 03 文档 §2 表格逐项核对（脚本内置 schema 断言）；
- 治理后抽检：脱敏列不可逆、漂移点入隔离记录、重复行去重率 100%。

## 3. 开发实施阶段

> 阶段编号对齐开发文档优先级（P0~P5），PROD 提到 P5，TRAJ 压到 P6 兜底。

### S0 地基（P0）— 已完成设计，进入搭建

- docker-compose 四容器骨架（postgres / platform-app / processing-app / portal-nginx）
- PG 五 schema（iam/proc/gov/ds/**prod**）初始化脚本 + 种子数据
- 公共模块：统一响应、异常、JWT、RBAC 注解、审计过滤器
- 前端 Vue3 骨架 + 登录页 + 路由守卫
- **出口**：容器全 healthy，admin 可登录空白门户

### S1 认证与权限（P1）

- 登录/刷新、用户/角色/权限管理页、ABAC 密级判定、审计查询页
- **出口**：admin/analyst/viewer 三角色登录，viewer 越权 403 可见

### S2 数据治理链路（P2，**演示主线一**）

- 上传接口 + 四模态处理器（pandas/openpyxl/Pillow/ffmpeg）
- PG 队列五阶段流水线 + 阶段时间线前端组件
- **质量检测增强**：质检规则引擎（NOT_NULL/RANGE/REGEX/ENUM 映射）+ 坏行隔离表 + **一键修复**（去重/填充/格式归一后重入队）
- 脱敏引擎：列名+内容双识别，掩码/哈希/置空
- **出口**：§2.2 全部样例走通，异常注入点全部按预期检出/修复

### S3 资产与质量（P3）

- 资产自动登记（internal 回调）、目录检索、血缘图（raw→processed→dataset→**product**）
- 热力图、数据标准与质量规则管理页
- **出口**：上传文件全部自动入目录，血缘可见，质量报告三维度出分

### S4 数据集（P4）

- 数据集筛选构建、版本快照、三维质检报告、版本对比
- **出口**：以治理后北斗轨迹资产建成"驾驶行为样本集"v1/v2 并对比

### S5 产品生成（P5，**演示主线二，新增**）

| 子功能 | 内容 |
|---|---|
| 产品配置 | 选数据集版本为原料 → 选模板（数据包/API服务/报告）→ 填元数据（名称/描述/分类分级/定价方式） |
| 生成引擎 | 数据包：按模板打包 processed 文件+README+质量报告为 zip；API 服务：注册到开放 API 路由并签发计量 Key；报告：Jinja 模板渲染 HTML→PDF |
| 合规校验 | 规则清单逐项检查（原料密级≤产品密级、敏感列已全部脱敏、质量分≥阈值、说明书完整），**不合规即拦阻并展示原因** |
| 说明书生成 | 按交易所口径自动填模板（来源/规模/字段/质量/更新频率/交付方式） |
| 预览与导出 | 产品详情页预览说明书；导出产品包 zip + 说明书 PDF |
| 登记挂牌 | 模拟登记凭证号生成 + 状态推进至 LISTED（不对接真实交易所，界面演示） |

- **出口**：从 S4 数据集生成 3 个产品（各一形态），1 个故意配错（密级倒挂）被合规拦阻

### S6 大屏串联（P5 并行）

- 四聚合接口扩展产品域指标（产品总数/各形态分布/合规通过率）
- 大屏新增"产品加工"板块；演示动线脚本固化

### S7 TRAJ 兜底（P6，**最低优先级**）

- 仅实现**模拟器产数**（按 JT/T 808 语义生成轨迹 CSV，产出物直接作为 §2.2 之外的补充数据源）
- 轨迹回放/查询/轨迹大屏**不做**；如时间充裕再补
- 已完成的 TRAJ 设计文档（MOD/UC/API/DDL 共 8 份）保留，不回删

## 7. 质量保障措施

### 7.1 关键测试用例（每功能点 ≥1 条，冒烟脚本固化）

| 编号 | 场景 | 预期 |
|---|---|---|
| T01 | 上传 5 万行 CSV | 五阶段全绿，行数一致，耗时 <60s |
| T02 | 漂移点/重复/乱序 | 全部入隔离记录并计数正确 |
| T03 | 敏感列（手机/身份证/银行卡） | 掩码/哈希正确且不可逆 |
| T04 | 图像 EXIF | 剥离后 exiftool 读不到 GPS |
| T05 | 处理中重启 processing-app | PENDING 不丢，自动续跑 |
| T06 | viewer 访问权限管理页 | 403 |
| T07 | 数据集 v1→v2 对比 | 增删项=实际差异 |
| T08 | 密级倒挂产品提交合规 | 拦阻且原因列表准确 |
| T09 | 产品包导出 | zip 内含数据+README+质量报告 |
| T10 | 大屏 10s 轮询 | 各板块数值与库内一致 |

### 7.2 演示完整性测试

- D-2 起每日按 §4 动线完整彩排，记录每步耗时与卡顿点；
- 准备"断网/容器重启/误操作"三个意外的恢复话术与预置还原快照（`pgdata` 卷备份）。

### 7.3 数据格式一致性验证

- 生成脚本内置断言：字段名/类型/取值域与 03 文档 §2 规范逐项比对，CI 式输出 PASS/FAIL 表；
- 治理后产物抽检 100 行人工核对。

### 7.4 体验优化

- 上传→阶段时间线全自动推进，无需手动刷新（3s 轮询）；
- 所有长任务给出进度百分比与当前阶段名；
- 演示前预置 admin 自动登录书签、大屏全屏快捷键说明卡；
- 每步演示界面右上角常驻"当前环节"面包屑，防止观众迷路。
