数据产品加工生成模块设计

版本：V1.0（总体设计，技术实现细节留待后续评审确定） 编制日期：2026-09-30 关联文件：《03-导航系统数据采集与应用平台设计.md》《01-数据中台功能与应用场景分析.md》 文档定位：在导航系统数据采集与应用平台中增设"数据产品加工生成模块"，把经过治理的北斗交通数据工厂化加工为可登记、可挂牌、可交付、可追溯的数据产品，满足数据交易所从产品登记到交易结算的全流程合规要求。

1. 概述

1.1 建设背景

平台已汇聚百万级车辆的北斗轨迹、ADAS/DSM 驾驶行为事件、视频片段及风险评分数据。项目说明明确要求"将采集的多维运行数据转化为可量化、可交易、可赋能的数据产品，服务于保险精算、企业安全管理、政府决策等多元场景"。数据不会因为被采集就自动成为可交易产品——从"数据资源"到"数据产品"需要经过一条受合规约束的加工与登记链路：

数据资源（合法采集）→ 治理加工（清洗/标准化/脱敏/质检）→ 产品封装（元数据/说明书）
   → 合规评估（来源/个人信息/权属/质量/安全）→ 产权登记（登记机构凭证）
   → 交易所挂牌 → 签约交易 → 安全交付（可用不可见）→ 结算与凭证 → 持续运营

1.2 政策与标准依据（2026 年现行）

依据 与本模块的关系
"数据二十条"（2022） 确立数据资源持有权、数据加工使用权、数据产品经营权"三权分置"，产品化即经营权的行使
国家数据局《数据产权登记工作指引（试行）》（2026-07 发布） 统一申请→受理→审查→公示→异议处理→信息存证→凭证核发登记程序；设 5 类登记类型覆盖权属全生命周期；登记凭证可在交易、入表、融资、司法场景全国互认
GB/T 36344-2018《数据质量评价指标》 产品质量评估报告的指标依据（完整性、准确性、一致性、时效性、可访问性等）
GB/T 37932-2025《数据安全技术 数据交易服务安全要求》 交易标的、交易过程安全规范
GB/T 43697-2024《数据分类分级规则》 产品数据分类分级标识
GB/T 46353-2025《大数据 数据资产价值评估》 定价与资产评估方法依据（成本法/收益法/市场法）
GB/T 36073-2025（DCMM） 数据管理能力成熟度背书
各交易所规则（以上海数据交易所为代表） 产品登记需提交产品说明书、合规评估报告（律师签字）、质量评估报告；挂牌审核；交付结算；12 个月无场内交易可摘牌
《数据安全法》《个人信息保护法》《汽车数据安全管理若干规定》 来源合规、告知同意、最小必要、出境管控

1.3 建设目标

  1. 加工工厂化：以流水线 + 可配置模板，把治理后的数据加工成多种形态的数据产品，不依赖逐个人工定制；
  2. 合规内生化：来源证明、个人信息授权、三权归属、脱敏、质量、安全等校验嵌入加工流程，不合规的产品无法提交登记；
  3. 登记材料自动化：自动生成数据产品说明书、质量评估报告等登记材料，对接登记机构与交易所系统；
  4. 交付安全化：敏感产品默认以 API 计量调用、隐私计算"原始数据不出域"方式交付；
  5. 全生命周期可追踪：产品从原料血缘到版本、登记凭证、合同、交付、结算、下架全程留痕可审计。

2. 数据产品形态与本平台产品规划

2.1 产品形态分类（与交易所口径对齐）

交易所交易标的通常分为数据集、数据服务、数据应用三类（API 数据集归入数据集）：

形态 定义 交付方式 本平台规划产品（示例）
数据集（数据包） 有明确主题、格式规范的数据集合 文件包交付 / 隐私计算空间内使用 《货运车辆驾驶行为精算样本集》《区域路网风险特征数据集》
API 数据服务 以接口形式按需查询的在线数据 REST/WebSocket，按次/周期计量 车辆风险评分查询、车辆风险事件订阅、历史轨迹合规查询
数据报告 加工形成的分析结论型产品 PDF/在线报告/定期推送 《车队月度安全体检报告》《区域货运安全运行月报》
数据服务（定制） 满足特定信息需求的处理结果 定制项目/SaaS 企业安全评级服务、靶向教育名单服务
数据应用/模型服务 以软件、算法、模型封装的产品 模型 API / 联合建模 UBI 保费浮动评分模型 API、双模态情绪识别模型推理服务

2.2 首批建议产品清单（北斗交通场景）

产品 形态 目标客户 敏感级 交付模式
车辆驾驶安全风险评分查询 API 保险机构、企业 中（单车查询需授权） 按次/包月
高危驾驶事件实时订阅 API/消息 保险风控 中 按车订阅
货运驾驶行为精算数据集（脱敏/聚合） 数据集 保险精算、再保 高（行踪轨迹衍生） 隐私计算空间内使用，原始数据不出域
区域货运安全运行月报 报告 行管、行业协会 低（聚合统计） 订阅推送
车队安全管理 SaaS（数据应用） 应用 运输企业 中（本企业数据） 账号年费
黑点路段风险特征数据 数据集 导航服务商、路政 低 文件/API

合规要点：单车级、个人级数据产品只能以"授权 + API 最小化返回"或"隐私计算"方式提供；不交付可识别到个人的明细数据包。

模块与平台现有模块的边界：

  • 复用：数据采集、存储、治理（标准/质量/血缘/分类分级）、统一权限、审计、隐私计算节点；
  • 本模块新增：加工流水线编排、产品工厂（模板/元数据/版本/生命周期）、合规校验引擎、登记材料生成、交易所对接、计量计费与合同交付管理。

4. 数据产品加工流水线

4.1 流水线阶段定义

采用 DAG（有向无环图）可视化编排，每个产品版本对应一条可复跑的加工流水线，所有节点产物入对象存储/库并登记血缘：

阶段 处理内容 输出
① 取数 从 DWD/DWS 层按主题选择数据源，固化取数 SQL/范围/时间窗 取数任务 + 数据快照引用
② 清洗 去重、缺失值处理、异常点剔除、逻辑矛盾过滤（沿用平台轨迹清洗规则） 清洗后明细
③ 转换 字段映射、类型转换、聚合统计、特征计算（如百公里急刹次数、夜间里程占比） 特征宽表/聚合表
④ 标准化 按国标/行标统一编码（808 报警码、行政区划代码、时间/单位/坐标系），字段命名与交易所数据包规范对齐 标准化数据集
⑤ 融合 关联主数据（车-企-人-路段），多源关联时生成融合血缘 融合数据集
⑥ 脱敏/匿名化 身份证/手机号/车牌掩码或哈希、k-匿名/差分隐私聚合、人脸剔除；按产品密级选择策略 脱敏产物
⑦ 质量门禁 按 GB/T 36344 跑质量规则，达标才放行；不达标阻断并生成整改单 质量评估结果
⑧ 封装 数据集打包（CSV/Parquet + 数据字典 + 样本说明）/ API 发布 / 报告渲染 / 模型部署 可交付产品版本

4.2 关键加工规则

  • 可复跑：同一产品版本基于数据快照与代码版本可重复构建（数据集版本不可变，更新走新版本）；
  • 审批节点：脱敏策略、取数范围、对外字段三类关键配置变更需安全/合规岗双人审批；
  • 禁止项内置：流水线配置校验硬性拦截——敏感个人信息出现在交付字段、未授权数据源、聚合粒度过细（可识别个人）等情形直接阻断；
  • 两种加工模式：
  • 离线批加工：精算数据集、月报等（调度系统按日/月触发）；
  • 在线服务化：风险评分 API 背后的特征计算走实时链路，产品定义中声明 SLA（时延、可用性）。

5. 产品元数据与产品说明书

5.1 元数据模型（产品级，区别于平台技术元数据）

元数据域 字段示例
基本信息 产品名称、产品编码、形态（数据集/API/报告/应用）、简介、关键词、所属行业（交通运输）、产品封面
权利信息 供方主体、持有权/使用权/经营权归属及证明、联合生产方及权益约定、授权链路
来源信息 数据来源（北斗终端采集）、采集场景/方式/范围/起止时间、告知同意证明、第三方数据许可
内容说明 数据主题、字段清单（名称/类型/含义/取值/密级）、样本量、时间跨度、更新频率、输入输出示例（API）
使用说明 使用目的、适用场景、使用条件与限制、禁止用途、转让规则、是否可二次加工
质量信息 GB/T 36344 各维度得分、质量评估报告编号、已知缺陷
安全信息 分类分级标识、脱敏/匿名化措施、交付方式、安全评估结论
交易信息 交易模式（公开挂牌/定向推送）、交付方式、定价方式、价格、SLA
登记信息 登记机构、登记类型、登记凭证编号、公示链接、挂牌证书编号、状态

5.2 数据产品说明书自动生成

依据交易所《数据产品说明书》规范，由元数据 + 加工流水线结果自动渲染为标准文档（PDF/A 版式 + 结构化数据双份），包含：产品概述、数据内容与字段说明、来源与权属说明、加工处理工艺说明、质量评估结论、安全与脱敏说明、使用限制、定价与交付方式、典型使用案例。说明书随产品版本归档，版本间差异自动生成变更说明（供变更登记使用）。

6. 定价策略配置

6.1 支持的定价模式（可配置、可组合）

模式 适用形态 本平台示例
按次调用 API 风险评分查询 X 元/次，阶梯量价
按周期订阅 API/报告/应用 按车包月订阅事件推送；SaaS 年费
按数据包一次性授权 数据集 精算样本集按批次授权费
按效果/分成 模型服务 UBI 模型按保费规模/减损效果分成
协议定价（一企一价） 全部 定向推送的大客户，线下洽谈后录入合同价
免费/公益 报告 行管监管月报（政务场景）

6.2 定价支撑能力

  • 计价规则引擎：配置计费维度（次数、车辆数、时长、数据量）、阶梯、免费额度、有效期；
  • 价格建议（辅助）：依据 GB/T 46353-2025，参考成本法（采集+加工+合规成本归集）、收益法（客户减损/增收益处分成测算）、市场法（同类产品挂牌价对标）给出建议价，最终由人工确认；
  • 计量：API 网关对每次调用出账（调用方、产品、版本、时间、结果状态），数据集交付按授权激活计量；
  • 优惠与对账：支持试用、优惠券（运营配置）、月度账单自动生成并与交易所/合同对账。

7. 合规性校验引擎（模块核心）

合规校验以"规则 + 证据"方式运行：每条规则给出通过/不通过结论，并绑定支撑证据（授权书编号、血缘节点、质量报告、脱敏作业 ID），证据链供律师与交易所审查。

校验域 规则示例 不通过处理
来源合规 数据源是否合法采集；采集场景方式范围是否有说明；终端入网协议/用户协议是否覆盖 阻断，补录采集合规说明
个人信息合规 是否履行告知同意义务并留存凭据；是否最小必要；敏感信息（人脸/行踪/健康）是否有单独授权；PIA 个人信息保护影响评估是否完成 阻断，走授权补全/PIA 流程
三权归属 持有权/使用权/经营权主体是否清晰；联合生产（平台/运输企业/保险）是否有权益约定；授权链是否完整 阻断，补权属协议
分类分级 是否完成 GB/T 43697 分级标识；重要数据/核心数据是否走相应审批；是否涉公共数据 阻断或转人工评审
质量门禁 GB/T 36344 六维（完整性/准确性/一致性/时效性/规范性/可访问性）是否达到产品声明等级；缺失率/错误率阈值 阻断，退回加工整改
脱敏安全 交付字段是否过脱敏策略；聚合数据是否通过 k-匿名/重识别风险评估；视频/人脸是否已剔除或匿名化 阻断
交易安全 交付方式是否符合 GB/T 37932-2025；API 是否鉴权限流审计；隐私计算交付方案是否可行；数据不出境承诺 阻断或限制交付模式
材料完整性 说明书、质量报告、合规评估报告、资产报告（如需）是否齐备且版本一致 阻断提交登记
禁入情形 是否属于登记指引中不予登记情形；是否涉依法禁止流通数据 系统硬拦截 + 合规岗复核

校验结果分三级处置：自动通过 / 人工评审 / 阻断；全部通过后自动汇编《合规自评估报告》，供第三方合规评估机构（律师）复核签字，平台不替代法定评估责任。

8. 产品登记与交易所对接

8.1 对接的两类机构（区分清楚）

  1. 数据产权登记机构（纳入国家数据产权登记机构目录的机构，接入国家数据产权登记服务平台）：办理数据产权登记，取得登记凭证（解决"是谁的、能不能交易"）；
  2. 数据交易所/交易中心（上海、北京、深圳、广州、贵阳等）：办理产品登记、挂牌、交易、结算、交易凭证（解决"卖给谁、怎么交付"）。

8.2 平台内办理流程（与机构程序一一对应）

9. 交易流程对接

9.1 交易全流程与系统支撑

环节 平台能力
供需对接 产品目录展示（公开挂牌同步交易所大厅；定向仅授权客户可见）、试用申请、需求询价
下单签约 对接交易所订单或场外合同；电子合同模板与用印流程；合同关键条款（用途限制、期限、禁止转售、保密）结构化入系统
交付授权 合同生效后自动开通：API 颁发 AppKey/Secret 并绑定限额、有效期、IP 白名单；数据集在隐私计算空间内授权可见；报告自动推送
交付执行 标准交付（平台 API/数据包）、生态交付（交易所沙箱/隐私计算空间）、自主交付（线下，登记交付凭证）三种模式留痕
计量结算 调用计量 → 出账 → 对接交易所资金结算或合同账期；发票信息管理；对账差异告警
交易凭证 交易完成后向交易所申请/同步交易凭证，凭证编号回写，作为收入确认、税务、入表依据
续约/终止 到期自动关停授权；续约沿用或新签合同；违约使用（超量/越权）自动熔断

9.2 "可用不可见"交付（高敏感产品默认路径）

  • 精算数据集类产品：需方在可信数据空间/隐私计算节点内编写分析任务，平台提供数据可见、不可下载的环境，仅输出聚合计算结果，操作全程录屏/日志存证；
  • 联邦学习：保险模型在双方节点间联合训练，梯度交互、原始数据不出域；
  • 所有交付行为（谁、何时、用哪个产品版本、执行了什么查询、输出去向）写审计链，关键环节哈希上链。

10. 产品模板管理

  • 模板即"产品配方"：模板固化某类产品的标准取数口径、加工 DAG、脱敏策略、质量门槛、元数据骨架、说明书框架、定价方式、交付模式、合规规则集；
  • 内置行业模板：风险评分 API 模板、脱敏精算数据集模板、安全月报模板、风险事件订阅模板；
  • 模板字段：模板名称、适用产品形态、数据源白名单、标准字段定义、必填元数据、默认密级与脱敏规则、质量阈值、交易所材料模板版本、审批流；
  • 模板治理：模板版本化（与交易所规则更新联动）、模板实例化后允许有限裁剪、模板升级对存量产品的影响评估与批量适配；
  • 好处：新产品上架从"从零做项目"变为"选模板 → 配参数 → 跑流水线"，登记材料与合规审查一次设计、反复复用，显著缩短上架周期。

11. 版本控制

对象 版本策略
产品版本 语义化版本（主.次.修订）：字段/口径/定价重大变化升主版本并触发变更登记；样本周期更新、缺陷修复升次/修订号
不可变原则 已交易版本不可变，调用合同始终绑定交付时的版本；新版本对老客户按合同约定平滑/强制迁移
关联版本 产品版本固化引用：取数快照、加工代码/模板版本、模型版本、脱敏规则版本、质量报告、说明书版本
差异比对 任意两版本自动比对字段、样本范围、口径、质量、价格差异，输出变更说明
灰度发布 API 类产品支持新旧版本并行、按客户灰度；数据集版本并存供不同合同调用

12. 全生命周期追踪

12.1 产品状态机

草稿 → 加工中 → 待合规审 → 合规通过/驳回 → 待登记 → 登记公示中 → 已登记
   → 待挂牌 → 已挂牌(在售) → 已停售(暂停) → 变更中(变更登记) → 已注销/已摘牌
                                                          ↘ 下架归档

12.2 追踪视图（一码到底）

每个产品分配唯一产品码，串联：

  • 向上血缘：产品 → 加工节点 → 治理层表 → 原始终端数据与采集合规凭据；
  • 横向记录：每个版本的元数据、说明书、三类报告、登记凭证、挂牌证书、补正往来；
  • 向下流水：曝光、询价、合同、授权、每次 API 调用/空间作业、账单、结算、交易凭证、客户使用反馈；
  • 事件时间线：状态流转、审批、机构反馈、下架原因全部入时间线；
  • 区块链存证：产品指纹（数据包哈希/模型哈希）、登记凭证、授权与关键交付记录上链，防篡改、支撑争议时举证；
  • 被动事件处理：登记异议、交易所补正/摘牌预警（如 12 个月无场内交易）、授权撤回、数据源合规失效（如车主撤回授权）自动触发产品暂停/召回评估。

14. 技术实现建议

方面 建议
架构形态 作为平台数据服务域的子模块，与治理服务、数据服务网关、隐私计算节点同体系；一期模块化实现，不新增重型中间件
流水线编排 复用平台调度能力（一期轻量调度，规模化接 DolphinScheduler）；加工节点以插件（取数/SQL/脱敏/质检/打包/发布）形式扩展
规则引擎 合规规则采用"规则库 + 可配置阈值"设计，法规与交易所规则更新时通过规则版本发布生效，不硬编码
材料生成 模板引擎渲染 PDF（说明书/报告），同时产出结构化 JSON 供 API 报送
交易所对接 适配层封装各交易所/登记机构 API；统一报文模型 + 字段映射配置；无 API 时导出申报包
计量计费 数据服务网关出账日志 → 流式聚合 → 账单；合同与定价规则独立配置
存证 联盟链/可信存证服务只存哈希与凭证编号，不存业务明文
前端页面 产品工作台（我的产品/状态看板）、流水线设计器、模板管理、合规审查台、登记台账、挂牌与订单、计量账单、生命周期时间线

15. 安全与合规保障

  • 等保三级：模块纳入平台等保范围，登记材料与权属文件按重要数据保护；
  • 权限分离：产品经理（加工配置）、合规岗（规则审批）、安全岗（脱敏/交付审批）、商务岗（定价合同）四权分立，关键动作双人复核；
  • 最小授权：加工任务按产品密级申请数据权限，任务结束自动回收；
  • 个人信息保护：PIA 前置、授权台账与产品血缘绑定，授权撤回可联动产品影响分析；
  • 审计与存证：全量操作日志 ≥6 个月（重要操作长期留存），关键证据上链；
  • 责任边界：平台完成自评估与材料编制，合规评估报告、质量评估报告、资产评估报告按交易所要求由具备资质的第三方数商出具，平台保留接口与证据组织能力。

16. 分期实施建议

阶段 内容
一期（随平台试点） 加工流水线（取数-清洗-标准化-脱敏-质检-封装）、产品元数据与说明书、合规引擎核心规则（来源/授权/脱敏/质量门禁）、API 产品计量计费、2 个模板（评分 API、月报）；先支持场外/合同交易闭环
二期 对接 1 家数据交易所（产品登记+挂牌+订单+凭证）与 1 家产权登记机构；隐私计算空间交付精算数据集；模板库扩充；版本与变更登记；区块链存证
三期 多交易所适配层、协议定价/效果分成、数据资产入表与融资材料支撑、产品运营分析（热度/收益/客户画像）、全国登记凭证互认对接

本文档为总体设计。各交易所/登记机构的具体字段清单、API 规格、材料模板以拟对接机构的最新规则为准，在详细设计阶段通过适配层配置落地。
