# 开发实现方案：代码可读可改保障计划

> 版本：v1.0 ｜ 日期：2026-09-30
> 依据：`docs/01-详细设计文档.md`、`docs/research/03`、`docs/research/04`
> 第一目标：**所有产出代码可读、可理解、可修改**；架构与文档为代码服务。

---

## Context（为什么需要这个方案）

项目当前只有设计文档，无任何代码。用户要求在开始编码前，先制定一个开发实现方案，确保：
1. 所有架构设计清晰可读——任何人拿到代码能快速理解系统结构
2. 所有功能代码可理解可修改——注释、命名、抽象层次到位
3. 各类接口文档齐全——API 不靠口口相传
4. 数据表设计完整有注释——DDL 即文档

本方案不涉及具体业务逻辑实现，而是建立**工程规范、项目骨架、分阶段实施路径**，作为后续所有编码工作的"宪法"。

---

## 0. 三大不可妥协的底线

1. **"读代码即读文档"**：每个 Java 类 / Python 模块 / Vue 组件，从文件名 + 顶部 Javadoc/Docstring + 包内 README 三处即可读懂"它是谁、做什么、被谁调用"。缺少这三者的 PR 不予合并。
2. **"接口先行、模块隔离"**：Java 模块间只能调用对方 `*-api` 子包里的 service 接口；Python 处理流水线所有可替换能力走抽象基类；前端跨页面逻辑走 composable/service 层。跨模块直连对方表或实现类的代码不予合并。
3. **"可追溯决策"**：所有非平凡技术决策写入 `docs/adr/NN-title.md`（≤ 80 行，含上下文/选项/决定/后果四节），代码里 `// 见 ADR-007` 即可找到根因。

### CI 自动化闸口（S0 一次性建好，所有阶段共用）

| 闸口 | 工具 | 失败处理 |
|---|---|---|
| Java 风格 | Checkstyle + Spotless（Google Java Style, 4 空格） | 阻断 |
| Java 静态分析 | SpotBugs + PMD + **ArchUnit**（校验模块依赖规则） | 阻断 |
| Python 风格 | Black + isort + flake8 + mypy（严格） | 阻断 |
| 前端风格 | ESLint + Prettier + TypeScript strict | 阻断 |
| 注释覆盖率 | JaCoCo（类级 100% 类注释）+ Python `interrogate`（≥ 90%） | 三次警告后阻断 |
| API 文档 | springdoc-openapi 自动生成，CI 校验非空 | 阻断 |
| DDL 注释 | `scripts/check_ddl_comment.py` 逐字段必须有 `COMMENT` | 阻断 |
| 提交信息 | commitlint（Conventional Commits） | 阻断 |

### A.5 命名规范

| 实体 | 规则 | 示例 |
|---|---|---|
| Java 包 | 全小写反域名 | `com.mydatama.platform.iam.service` |
| Java 类 | UpperCamelCase；接口无 `I` 前缀，实现加 `Impl` | `UserService` / `UserServiceImpl` |
| Java 方法 | lowerCamelCase 动词开头 | `findEnabledUsersByDept` |
| Python 模块/函数 | snake_case | `stage4_mask.py` / `acquire_job_skip_locked` |
| Vue 组件文件 | UpperCamelCase `.vue` 多词名 | `AssetLineageGraph.vue` |
| 数据库表 | `<schema>.<单数蛇形>` | `iam.user`, `proc.job_queue` |
| 数据库列 | 蛇形，公共字段统一 | `created_at`, `created_by`, `deleted` |
| 索引/外键/唯一 | `idx_/fk_/uk_<表>_<列>` | `idx_job_queue_status_created_at` |
| REST 路径 | 复数蛇形小写，嵌套 ≤ 2 层 | `/api/governance/assets/{id}/lineage` |
| Commit | Conventional Commits | `feat(processing): add CSV mask stage` |

### A.6 代码注释规范

**Java Javadoc 模板**（每个 public 类与方法必须）：
```java

 * 资产检索服务实现。
```

```python
"""阶段四：脱敏。被 PipelineRunner 调用，调用 MaskerRegistry 执行实际脱敏。"""

class Masker(Protocol):
    """脱敏器接口。所有具体脱敏器实现此接口。"""

    def mask(self, value: str) -> str:

        Args:
            value: 原始明文值。
        Returns:
            脱敏后字符串。
        """
```

**Vue 组件顶部注释**：

**禁止**：复述代码的废话注释、块注释（统一用 Javadoc/Docstring）、无 issue 号的 TODO。

### A.7 API 文档规范

- Java：springdoc-openapi 注解（`@Operation`/`@Parameter`/`@ApiResponses`），CI 抓 `/v3/api-docs` 存 `docs/api/`
- Python：FastAPI 自带 OpenAPI，每个端点必须有 `summary`/`description`/`response_model`/`tags`
- 合并：`scripts/merge_openapi.py` 合并两份为 `docs/api/openapi.yaml`
- 前端：`openapi-typescript` 从 YAML 生成 TS 类型，**禁止手写 DTO 类型**
- Swagger UI 挂在 `/api/docs`（演示环境关闭）

### A.8 数据库文档规范

- DDL 按 `docs/ddl/<schema>/NN_xxx.sql` 编号，每文件顶部头注释写 schema 目的与表清单
- 每张表 `COMMENT ON TABLE`，每个字段 `COMMENT ON COLUMN` 写**业务含义**
- ER 图用 dbml.org 语法维护 `docs/er/mydatama.dbml`，CI 反向校验 DDL 与 dbml 一致
- 索引必须注释命中场景：`COMMENT ON INDEX idx_xxx IS '命中: 按状态拉取待处理任务'`
- 字段变更走 Flyway 迁移 `V00X__<描述>.sql`

### 关键表 DDL（完整版在 `docs/ddl/`，此处节选核心表）

**iam.users**（用户）：
```sql
CREATE TABLE iam.users (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username      varchar(64)  NOT NULL,
    password_hash varchar(72)  NOT NULL,          -- BCrypt hash
    real_name     varchar(64)  NOT NULL,
    dept_code     varchar(32)  NOT NULL,          -- ABAC 用
    secret_level  int          NOT NULL DEFAULT 1,-- 1公开 2内部 3秘密 4机密
    enabled       boolean      NOT NULL DEFAULT true,
    locked_until  timestamptz,                    -- 登录失败锁定期
    fail_count    int          NOT NULL DEFAULT 0,
    last_login_at timestamptz,
    -- 公共字段省略
);
COMMENT ON TABLE  iam.users IS '平台用户表';
COMMENT ON COLUMN iam.users.secret_level IS '用户密级，ABAC 校验 asset.secret_level <= user.secret_level';
CREATE UNIQUE INDEX uk_users_username ON iam.users(username) WHERE deleted = false;
```

**iam.policies**（ABAC 策略）：
```sql
CREATE TABLE iam.policies (
```

**proc.job_queue**（PG 任务队列，SKIP LOCKED 抢占）：
```sql
CREATE TABLE proc.job_queue (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    file_id       bigint NOT NULL REFERENCES proc.data_files(id),
    stage         varchar(32) NOT NULL,            -- COLLECT/CLEAN/STANDARDIZE/MASK/REGISTER
    status        varchar(16) NOT NULL DEFAULT 'PENDING',
    retry_count   int NOT NULL DEFAULT 0,
    locked_at     timestamptz,
    locked_by     varchar(64),                     -- worker: host:pid:thread
    metrics       jsonb,
    mask_columns  jsonb,
    error_msg     text,
    error_stage   varchar(32),
    ls_project_id varchar(64),
    ls_task_id    varchar(64),
    started_at    timestamptz,
    finished_at   timestamptz
);
COMMENT ON TABLE proc.job_queue IS '处理任务队列，FOR UPDATE SKIP LOCKED 抢占；RUNNING 超 5 分钟启动恢复';
-- 抢占 SQL: UPDATE proc.job_queue SET status='RUNNING'... WHERE id = (SELECT id FROM proc.job_queue WHERE status='PENDING' ORDER BY id FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING *;
```

## D. API 设计

### 统一响应体

```json
{
  "code": "OK",           // OK / AUTH_* / BIZ_* / SYS_*
  "message": "成功",
  "data": { ... },
  "traceId": "a1b2c3d4"   // 串联日志/审计/前端报错
}
```

### 认证鉴权

- 登录 `POST /api/auth/login` → `accessToken`(2h) + `refreshToken`(7d)
- 请求头 `Authorization: Bearer <token>`，Java Filter 解析 → RBAC `@RequirePermission` 切面 → ABAC 引擎
- Python 本地同密钥验签；细粒度场景调 Java `/internal/authz`
- 开放 API：`X-Api-Key` 头；内部接口：`X-Service-Token` 头

### 各模块核心 API

| 模块 | 关键端点 |
|---|---|
| iam | `POST /api/auth/login`、`GET /api/auth/me`、`GET /api/iam/users`、`GET /api/audit/logs` |
| processing | `POST /api/processing/files/upload`、`GET /api/processing/files/{id}`、`GET /api/processing/jobs/{id}`、`POST /api/processing/jobs/{id}/retry` |
| governance | `GET /api/governance/assets`、`GET /api/governance/assets/{id}/lineage`、`GET /api/governance/heatmap`、`GET /api/screen/overview` |
| dataset | `POST /api/datasets`、`POST /api/datasets/{id}/versions`、`GET /api/datasets/{id}/versions/{vid}/report`、`GET /api/datasets/{id}/versions/compare` |
| 内部 | `POST /internal/assets/register`、`POST /internal/audit`、`POST /internal/authz` |
| 开放 | `GET /openapi/v1/assets`、`GET /openapi/v1/datasets` |

## F. 构建与部署

### Maven 构建

- 父 POM 锁定所有版本 + `pluginManagement`（Checkstyle/Spotless/SpotBugs/ArchUnit/JaCoCo/springdoc/jib）
- `platform-boot` 是唯一有 `spring-boot-maven-plugin repackage` 的模块
- `jib-maven-plugin` 构建镜像（不用 Dockerfile，分层更优）

### Docker Compose

4 容器（core）+ 1 容器（label profile）：
- `postgres:16-alpine`（唯一中间件，自动建库建表插种子）
- `platform-app`（Java，Xmx 640MB）
- `processing-app`（Python，worker 线程 2）
- `portal-nginx`（前端静态 + 反向代理）
- `label-studio`（可选 profile）

开发覆盖 `docker-compose.dev.yml`：挂源码热重载、Java debug 5005、前端 5173。

### 环境分级

| 环境 | 特征 | 用途 |
|---|---|---|
| dev | 挂源码热重载 | 日常开发 |
